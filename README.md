# LLM QA 이슈 자동 분류 (오프라인)

사용자 발화 / 실제 응답이 담긴 시트를 넣으면 **이슈 유형 · 판단 근거 · 검토 필요 여부**를 자동 생성하고
QA 리포트를 만들어 줍니다. **외부 API를 전혀 사용하지 않습니다** (규칙 엔진 + 선택적 로컬 학습 모델).

## 🌐 배포

**https://llm-app-classifier-hpvpgkavcruub3pi8v4yk5.streamlit.app/** (Streamlit Community Cloud)

- 설치 없이 브라우저에서 바로 사용할 수 있습니다. 이 저장소의 `main` 브랜치가 배포됩니다.
- 배포 버전에서는 업로드한 시트가 Streamlit Cloud 서버에서 처리됩니다 (외부 AI API 호출은 없음).
  사내 데이터를 외부 서버에 올리면 안 되는 경우에는 아래 **실행** 방법으로 PC에서 실행하세요.
- 배포 버전에서 저장한 규칙(`data/rules.json`)과 추가 학습 데이터(`data/labeled.csv`)는
  앱이 재시작되면 초기화됩니다. 계속 쓸 학습 데이터는 `training/base_labeled.csv`에 반영해 커밋하세요.
- 앱 화면의 판단 근거에 과거 이슈 문구가 표시되므로, 앱 공개 범위는 Streamlit Cloud 설정에서 관리하세요.

```
① 테스트 결과 업로드 → ② LLM 응답 이슈 분석 → ③ 이슈 유형 자동 분류 → ④ QA 리포트 자동 생성
   Excel / CSV          발화 의도 × 응답 유형      GA / 대화 정책 / 음성인식 등   이슈 현황·유형별 통계·검토 필요 항목
```

## 실행

```bash
pip install -r requirements.txt
streamlit run app.py              # 웹 UI (http://localhost:8501)
python -m qa_classifier 결과.xlsx  # UI 없이 바로 Excel 리포트 생성
```

## 입력 시트 형식
Excel(.xlsx) 또는 CSV(UTF-8 / CP949). **맨 위에 제목줄·빈 줄·시험자 줄이 있어도 됩니다** — 헤더 행(컬럼 이름 줄)을 자동으로 찾습니다.
컬럼 순서는 상관없고, 아래 **컬럼 이름**만 맞으면 됩니다.

### ① 테스트 결과 시트 (pass / fail) — 테스트 진행 원본
시험자별로 `실행결과`(pass/fail) 블록이 반복되는 양식. 한 시트에 표가 여러 개(예: 일상대화 / 일반QA) 있어도 됩니다.

```
📌 제목 (선택)
                                                   TT261103051                    TT261103050       ← 시험자 ID (실행결과 컬럼 바로 위)
일상대화                                            4                              3                 ← 구분·건수 (선택, 무시)
순번 | 카테고리 | 사용자 의도 | 발화 | 시험방법 | 기대결과 | 실행결과 | 비고1 | 재현일시 |  | 실행결과 | 비고2 | 재현일시
1    | 일상대화 | Chit Chat  | 오늘 기분이 좋아 | … | …   | pass     |       | 15:03    |  | fail     | DIM 미노출 | 14:46
```

| 컬럼 | 필수 | 설명 |
|---|---|---|
| 발화 | ✅ | 사용자 발화 |
| 실행결과 | ✅ | `pass` / `fail` (대소문자 무관). 시험자마다 한 번씩 반복 가능. 빈칸은 미실행으로 보고 제외 |
| 비고 | 권장 | 실행결과 바로 오른쪽의 `비고…` 컬럼 = **fail 사유(문제점)**. 분류의 핵심 근거 |
| 기대결과 | 권장 | 기대 응답(실제 응답 대신 사용) |
| 순번 · 카테고리 · 사용자 의도 · 시험방법 · 재현일시 | 선택 | 결과와 이슈리스트에 그대로 옮김 |
| (실행결과 위 셀) | 선택 | 시험자 ID → 이슈리스트의 `SAID`. 없으면 시험자1, 시험자2… |

처리: 시험자별 실행 1건 = 1행으로 펼친 뒤 **pass → 정상**, **fail → 비고를 문제점으로 보고 관련시스템·등급 분류**.
④에서 **이슈리스트 양식으로 받기**를 누르면 fail 건만 모아
`순번 · 등급 · 경로 · 방법 · 결과 · 기대 · 문제점 · 특이사항 · 관련시스템 · 시험자 · SAID · 재현일시` 양식으로 내려받습니다
(방법은 `"발화" 발화` 형식, 시험자별로 묶음, 뒤에 세부 이슈·판단 근거·검토 필요 추가).

### ② 이슈리스트 (fail 건 정리본)
```
📌 이슈리스트
순번 | 등급 | 경로 | 방법 | 결과 | 기대 | 문제점 | 특이사항 | 관련시스템 | 시험자 | SAID | 재현일시
1    |      |      | "현재 프로야구 팀 순위 알려줘" 발화 | | 현재 프로야구 1위는… | 무지개색 DIM … 미노출 | | | | TT261103051 | 2026-11-23 14:05
```
- `방법`(또는 발화·발화내용) → 사용자 발화, `결과`(비어 있으면 `기대`, 또는 응답결과) → 응답, `문제점`(또는 이슈설명) → 분류 근거
- 이슈리스트(문제점 컬럼이나 등급 컬럼이 있는 시트)는 모든 행이 이슈이므로 **정상으로 판정하지 않습니다.**
  문제점 컬럼을 못 찾으면 화면에 경고가 뜨니 이슈 설명 컬럼을 직접 골라 주세요.
- `등급`·`관련시스템`이 비어 있으면 채워서 내려받기, **QA가 이미 입력했으면** `등급(QA)`로 보존하고 자동 판정과 일치율 표시
  (등급·관련시스템이 입력된 과거 이슈리스트는 사이드바에서 추가 학습 데이터로도 쓸 수 있음)

### ③ 발화 · 응답만 있는 시트
| 컬럼 | 필수 | 인식하는 이름 |
|---|---|---|
| 사용자 발화 | ✅ | 사용자 발화, 발화, 질의, utterance … |
| 실제 응답 | ✅ | 실제 응답, 응답, 답변, 결과, response … |
| 문제점 | 선택 | 문제점, 이슈설명, 이슈 내용, 현상 → 있으면 1순위 근거 |
| STT 결과 | 선택 | STT, 인식 결과, ASR → 발화와 비교해 음성인식 오류 판단 |

문제점이 없으면 발화 의도(질문/명령)와 응답 유형으로 정상·이슈를 판단합니다.

## 판단 방식
**② 분석** — 각 행에서
- 발화 의도: 정보성 질문 / 기능 실행 요청 (예: `어디`, `?` / `켜줘`, `~줄래?`)
- 응답 유형: 기능 실행·화면 이동 / 결과 없음 / 미지원 안내 / 인식 실패 / 오류 / 무응답 / 일반 응답
- 발화-응답 핵심어 연관도 (조사·어미 제거 후 비교)

**③ 분류** — 조합 규칙으로 판정 (예시)
| 발화 | 응답 | 이슈 유형 | 판단 근거 |
|---|---|---|---|
| 정보성 질문 | 기능 실행/화면 이동 | GA | 정보성 질문을 기능 실행 의도로 오인 |
| 기능 실행 요청 | 결과 없음 | GA | 요청 기능 실행 실패 및 검색 결과 없음 |
| 기능 실행 요청 | 다른 기능 실행 | GA | 요청과 다른 기능을 실행함 |
| 기능 실행 요청 | 미지원 안내 | 대화 정책 | 미지원·불가 안내 (정책상 정상인지 확인 필요) |
| 질문 | 관련 없는 응답 | 대화 정책 | 동문서답 의심 |
| - | 재발화 요청 / STT 불일치 | 음성인식 | 발화 인식 실패 |
| - | 무응답 / 오류 안내 | 시스템 오류 | … |

**문제점 컬럼이 있을 때** — 운영 지침(관련시스템 분류 기준 · 등급 기준)에 따라 판정. 사이드바에서 규칙 편집 가능.

| 관련시스템 | 판단 기준 | 문제점 문구 예 → 세부 이슈 / 기본 등급 |
|---|---|---|
| 대화 정책 | 예상 서비스 시나리오를 벗어난 경우 | "그런 말씀을 하시면 제가 너무 슬퍼요" → 시나리오 선택 오류 / Major |
| 음성인식 | 말한 내용을 잘못 인식 (STT) | "2번 시즌 서울 에스케이 인식 >" → 오인식/미인식 / Major |
| 음성합성 | 텍스트를 잘못 읽음 (TTS) | "'킬로바이트 스타즈'로 발음" → 숫자/고유명사 음성전환 오류 / Minor |
| GA | 발화→이해→AI 결과→응답/실행 흐름이 깨짐 | "혹시 ○○ 시청을 원하셨나요?" → 의도오해 / Major<br>"응답 없이 대화 강제 종료" → 응답미출력/종료 / Major<br>"정보 오류 / 확인되지 않은 / 현 시점 기준 과거" → AI 결과 오류 / Minor<br>"질문했으나 / 누락" → 의도오해(부분 응답) / Minor<br>"무지개 DIM / 메타포 / QR 미노출" → 기가지니 UI 오류 / Minor |
| 홈포털 | 결과 화면 표시·UX 문제 | "추천 콘텐츠 / 포스터 미노출 / 클릭·이동 오류 / UI 깨짐" → Minor |

| 등급 | 기준 |
|---|---|
| Critical | 시청에 큰 문제 (먹통, TV OFF, 화면 이상), 유해성 → 해당 문구가 있으면 자동 상향, 항상 검토 |
| Major | 사용자 의도와 크게 다르게 동작 (기능 실행 안 함, 상관없는 기능 실행) |
| Minor | 의도와 다르나 큰 불편 없음, 부정확한 정보(Hallucination) |
| Request | 중의적 요청이 원인, 현재 미지원 기능, 제언사항 → 해당 문구가 있으면 Request |

한 문제점에 여러 이슈가 섞이면 **등급이 높은 것 → 규칙 목록 위쪽** 순으로 대표를 정하고 나머지는 **보조 이슈**로 표시합니다.
서로 다른 관련시스템이 섞이면 검토 필요(Y)로 표시합니다.

**결과 내려받기**
- 원본 양식 그대로 `등급`·`관련시스템` 칸을 채운 Excel (세부 이슈·판단 근거·검토 필요를 뒤에 추가)
- QA 리포트 Excel / HTML
- 시트에 QA가 이미 입력한 등급·관련시스템이 있으면 `등급(QA)`로 보존하고 자동 판정과의 일치율을 보여줍니다.

**검토 필요 = Y** 조건: 신뢰도 < 기준값(기본 0.7), 항상 검토할 유형(기본: 대화 정책), 학습 모델과 판정 불일치.

규칙 키워드(정규식)와 기준값은 사이드바에서 수정·저장할 수 있습니다 (`data/rules.json`).

## 학습 모델 (기본 사용)
과거 이슈리스트의 **QA 판정(등급·관련시스템)** 을 학습해 판정합니다. 외부 API 없이 이 PC에서만 동작합니다.

- 기본 학습 데이터: `training/base_labeled.csv` — 과거 5개 회차 874건
- **관련시스템 분류표**: `training/guideline.csv` — 운영 지침의 판단 기준·대표 이슈 문장을 학습에 함께 사용 (5배 가중).
  사이드바 **관련시스템 분류표**에서 수정·파일 교체 가능 (`관련시스템 · 판단 기준 · 대표 이슈` 컬럼, 대표 이슈는 쉼표 구분)
  (260701 GG4 · 260727 GG3 · 260901 GGA · 261006 GG4 · 261123 GG4)
- 판정 방식
  - **관련시스템**: 시스템별로 해당 여부를 판단 → 여러 개 가능 (예: `대화 정책, GA, 홈포털`)
  - **등급**: Critical / Major / Minor / Request 중 하나
  - **판단 근거**: 규칙이 찾은 세부 이슈 + **가장 비슷한 과거 이슈와 그때의 QA 판정**
    예) `유사 과거 이슈 [260727 GG3 #30] '“설정메뉴로 이동합니다”라는 안내가…' → 대화 정책, GA, 홈포털 / Major (유사도 94%)`
  - 음성인식·음성합성은 키워드 규칙이 더 정확해 규칙 결과를 더해줍니다. 먹통·TV OFF·유해 등은 Critical로 보정.
- **검토 필요 = Y** (학습 모델 사용 시): 신뢰도 < 0.7, 비슷한 과거 이슈가 없음(유사도 < 30%),
  아주 비슷한 과거 이슈(유사도 ≥ 60%)와 판정이 다름, 항상 검토할 등급/관련시스템
- 처음 실행 시 자동 학습(수 초), 학습 데이터가 바뀌면 자동 재학습

**정확도 (처음 보는 회차 기준 — 회차 하나를 빼고 학습한 뒤 그 회차를 맞힌 결과)**

| | 등급 일치 | 관련시스템 완전 일치 |
|---|---|---|
| **5개 회차 (11월 포함), 재검토 판정 + 분류표** | **85%** | **80%** |
| 4개 회차, 재검토 판정(관련시스템·등급 새 기준) + 분류표 | 87% | 83% |
| 관련시스템만 재검토 + 분류표 | 65% | 83% |
| 이전 판정 + 분류표 | 65% | 55% |
| 이전 판정 | 64% | 52% |
| 키워드 규칙만 | 41% | 9% |

**관련시스템 기준** (분류표에 반영)
- **대화 정책**: 애초에 잘못된 서비스나 시나리오를 선택했다 (의도 분류 오류, 시나리오 선택 오류)
- **GA**: AI 응답이나 기능 실행 과정에서 정상적인 처리가 이루어지지 않았다 (동작 미연계, 응답 오류, 기능 실행 실패)
- **대화 정책, GA**: 잘못된 시나리오를 선택했고, 그것과 구분되는 별도의 응답·실행 오류도 발생했다

| 261006 GG4 | 92% | 68% |
| 261123 GG4 (새 이슈 유형) | 69% | 67% |

- 261123 GG4(11월)는 무지개 DIM·메타포 미노출, AI 답변 정보 오류 등 **처음 나온 이슈 유형**이라 과거 이력이 없었습니다 (평균 유사도 25%).
  QA가 116건을 확인해 학습 데이터에 추가했고, 이후 같은 시트의 검토 필요는 101건 → 4건.

- 261006 GG4는 "메뉴 이동 안내 후 설정 화면 연결 실패(→ GA)" 표현이 이 회차에만 있어 낮습니다.
  분류표에 GA·대화 정책 구분 문장(안내는 맞게 했으나 실행 실패 → GA / 다른 기능·메뉴로 분기 → 대화 정책)을 추가해 51% → 72%.
  (이 문장은 해당 회차 오답을 보고 추가해서 이 회차 수치는 다소 낙관적입니다.)
- 비슷한 과거 이슈가 있을수록 정확합니다.

**등급 기준** (QA가 과거 판정 758건을 이 기준으로 재검토해 반영, 2026-11-26)
- **Critical**: 시청에 큰 문제를 발생시키는 경우 (먹통, TV OFF, 화면 이상 등), 유해성
- **Major**: 사용자 의도와 크게 다르게 동작하는 경우 (기능 실행하지 않음, 전혀 상관없는 기능 실행 등)
- **Minor**: 사용자 의도와는 다르나 큰 불편은 없는 경우, 부정확한 정보 제공 (Hallucination)
- **Request (검토요청)**: 중의적인 요청이 원인이 되어 문제되지 않는 경우, 현재 기준 미지원 기능, 제언사항 등

재검토 후 등급 분포는 Major 604 · Minor 109 · Request 42 · Critical 3 (이전: Major 395 · Minor 241 · Critical 88 · Request 34).
Major가 80%라 "전부 Major"로만 찍어도 79.7%이므로 등급별로 보면:

| 등급 | 재현율 | 정밀도 |
|---|---|---|
| Major | 94% | 92% |
| Minor | 75% | 69% |
| Request | 33% | 67% |
| Critical | 33% (3건) | — |

**검토 필요 기준 고르기** (5개 회차, 처음 보는 회차 기준 — 관련시스템·등급이 둘 다 맞아야 정답, 정답률 70%)

| 신뢰도 기준 | 검토할 행 | 오답 중 검토 Y로 잡히는 비율 | 검토 N 행 정확도 |
|---|---|---|---|
| 0.6 | 36% | 65% | 84% |
| **0.7 (기본)** | 50% | 84% | 91% |
| 0.8 | 59% | 92% | 94% |

자동 판정을 그대로 쓰기보다 **검토 Y만 사람이 보는 방식**을 권장합니다. 검토량을 늘려도 놓치는 오답을 줄이려면 사이드바에서 0.8로.

**남은 약점 (정확도를 더 올리려면)**
- **Request**를 대부분 Major로 판정 → Request 사례(현재 42건)가 더 필요합니다.
- **Critical**은 학습 사례가 3건뿐이라 모델이 배우지 못합니다. 먹통·TV OFF·화면 이상·유해 문구가 있으면 규칙으로 Critical로 올립니다.
- 사례가 적은 관련시스템(음성인식 9건, 음성합성 10건, 홈포털 7건)은 학습 데이터가 더 필요합니다.

**학습 데이터 늘리기**
- 사이드바 **과거 이슈리스트로 추가 학습**: 등급·관련시스템이 입력된 시트를 올리면 `data/labeled.csv`에 추가
- ③ 단계 **검수 결과 학습 데이터로 저장**: 수정·확인한 결과(검토 필요 = N)를 추가
- **모델 다시 학습 + 정확도 측정**: 회차별 정확도를 다시 잼
